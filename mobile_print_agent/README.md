# SmartWagers Print Companion (Android / iOS / Chrome OS)

Companion app for ESC/POS receipt printers. Tellers keep using the SmartWagers
**web UI** in the browser; this app stays signed in, claims print jobs from the
Django queue, and writes raw ESC/POS over Bluetooth and (on Android / Chromebook)
USB host.

## Architecture

1. Browser places a bet → receipt JSON is created as today.
2. If the Windows localhost agent (`127.0.0.1:8765`) is not healthy, the browser
   POSTs the receipt to `/api/print-jobs/`.
   - **Chrome OS** and mobile browsers fall back to this queue in `auto` mode.
   - Windows desktops stay on the localhost agent unless
     `smartwagersPrintMode=server`.
3. The server renders ESC/POS bytes (same layout as Windows `escpos` mode).
4. This companion polls `/api/print-jobs/pending/` (and optionally
   `ws/print-jobs/`) then prints.

## Platform transport notes

| Platform | Transport | Printer requirement |
| --- | --- | --- |
| Android / Chromebook (ARC) | Classic Bluetooth SPP | Pair in system settings first (e.g. XP-58 / similar 58mm) |
| Android / Chromebook (ARC) | USB host bulk-OUT | Plug in; allow USB access when prompted |
| iOS | BLE GATT only | **Must** be BLE or dual-mode. Classic-SPP-only printers will not appear |

Apple does not expose Classic Bluetooth SPP or USB host to third-party apps.

## Chrome OS (Chromebook)

The Windows agent (`local_print_agent`) cannot run on Chrome OS. Use this
companion instead:

1. Chromebook must have **Google Play / Android apps** enabled (policy may
   block this on managed devices).
2. Install the companion (managed Play preferred — see Distribution below).
3. Sign in with the **same teller** used in Chrome.
4. Scan Bluetooth and/or USB printers → Test print → **Start service**.
5. Bet in Chrome; receipts queue to the companion.

## Distribution

### Managed fleets (recommended for Chromebooks)

1. Build a signed **AAB** (or APK) with a release keystore (`npm run build:android:eas`
   or local Gradle with your upload key).
2. Upload to Google Play as a **private / unlisted** app (or internal testing track).
3. In **Google Admin console** → Devices → Chrome → Apps & extensions, force-install
   `com.smartwagers.printcompanion` on the teller OU.
4. Ensure the OU allows Android apps / Play Store.

Sideloading is usually blocked on enterprise Chromebooks without developer mode.

### Unmanaged / lab devices (ADB sideload)

1. Enable Linux or developer mode as required by the Chromebook model; enable ADB.
2. Download `SmartWagers-PrintCompanion.apk` from **Admin → Print Agent**.
3. `adb install -r SmartWagers-PrintCompanion.apk`

Local release APKs currently use the Expo/RN debug signing config for fast
sideload. Use a dedicated upload/release keystore before Play Store distribution.

## Setup (development)

Requires a **dev client / prebuild** (not Expo Go) because Classic BT, BLE, USB,
and the foreground service use native modules.

```bash
cd mobile_print_agent
npm install
npx expo prebuild
npx expo run:android
# or
npx expo run:ios
```

Set the **Server URL** to your SmartWagers LAN URL (e.g. `http://192.168.1.10:8000`),
sign in with a teller or admin account, scan/select the printer, run **Test print**,
then leave **Start service** on while using the browser.

## Production builds

### Android APK (sideload)

From WSL/Linux (requires JDK 17 + Android SDK):

```bash
cd mobile_print_agent
npm install
npm run build:android
```

Or manually:

```bash
npx expo prebuild --platform android
cd android && ./gradlew assembleRelease
```

Copy / resulting artifact:

```text
mobile_print_agent/dist/SmartWagers-PrintCompanion.apk
```

Admins can download it from **Admin → Print Agent** when that file exists.

**Deploying to a Windows server:** copy **only** that APK into
`mobile_print_agent/dist/` on production. Do **not** copy `node_modules/`,
`android/`, `ios/`, or `.expo/` — those paths exceed Windows’ classic filename
limit and cause “file name is too long” errors (often surfacing on `.png`
cache files). Build on WSL/Linux/macOS (or EAS), then either:

```bash
# preferred: slim Windows-safe folder
./prepare_windows_copy.sh /mnt/e/SmartWagersReleases/mobile_print_agent
```

or transfer the single APK.

### iOS

iOS cannot be compiled on Linux/WSL. The native `ios/` project is generated by prebuild; build it on a Mac or via EAS cloud:

```bash
cd mobile_print_agent
npx eas login
npx eas build --platform ios --profile preview
```

Or on macOS with Xcode + CocoaPods:

```bash
npx expo prebuild --platform ios
npx expo run:ios --configuration Release
```

Requires an Apple Developer account for device / TestFlight / Ad Hoc installs.

Cloud Android alternative (no local SDK):

```bash
npx eas login
npm run build:android:eas
```

## Teller checklist

1. Pair the Bluetooth printer in OS settings (Android / Chromebook) **or** plug
   USB and allow access; on iOS use a BLE / dual-mode printer.
2. Open SmartWagers Print, enter the server URL, sign in.
3. Scan → select printer → Test print.
4. Start service and keep the notification (Android) or screen (iOS) alive.
5. Use Chrome/Safari on the same device (or another session as the same teller)
   for betting; receipts queue to this companion.

## USB module

Android USB host support lives in the local Expo module
`modules/usb-escpos/` (`usb-escpos` package). It lists USB devices and writes
raw ESC/POS via bulk-OUT after the system permission dialog.

## Chromebook compatibility

`plugins/withChromebookCompat.js` marks touchscreen / bluetooth / usb.host as
`required=false`, unlocks orientation, and sets `resizeableActivity=true` so
non-touch Chromebooks and ARC windowing are not filtered out of Play.

## API used

- `POST /api/print-devices/login/`
- `POST /api/print-devices/register/`
- `GET  /api/print-devices/health/`
- `GET  /api/print-jobs/pending/`
- `POST /api/print-jobs/<id>/ack/`
- `WS   /ws/print-jobs/?token=…`
